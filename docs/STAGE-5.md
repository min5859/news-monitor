# 5단계 — 실제 뉴스가 있는 자동 샘플

작업일: 2026-10-18 KST.

## 목적과 계획

빈 실패 화면이 아니라 실제 다매체 기사와 검증된 분석 결과를 보여준다.

1. 최근 실제 뉴스와 발행일을 검색으로 확인한다. 오래된 기사·주가 페이지·관련 기사 영역을
   최신 대상 기사로 오인하지 않는다. 제목·링크·매체·발행일만 수집한다.
2. 기존 로그인된 Codex CLI의 읽기 전용 실행을 검증한다. shell·MCP/앱·플러그인·하위 에이전트·
   이미지 생성은 끄며 사용자 설정/인증을 복사하거나 커널 보안을 바꾸지 않는다.
3. 사용 가능한 경우 웹 검색 수집과 제목 분류를 자동 파이프라인으로 연결한다.
   GDELT 관측 시각과 기사 발행일을 구분하고, 수집 경로/모델을 사실대로 표시한다.
4. 관련성·기간·중복·출처·JSON·근거 검증을 유지하고 `회장님`으로 표시한다.
5. 실제 데이터로 로컬 화면을 갱신하고 기사 링크·집계·필터를 확인한다.
6. 과정·실패·실제 확보량과 운영/배포 잔여 작업을 이 문서와 OCI wiki에 기록한다.

GitHub Pages나 정기 실행이 이미 완성됐다고 하지 않는다. 실제 수집과 모델 실행을
검증하기 전 보안 제한을 해제하거나 기존 OCI 게시기 설정을 바꾸지 않는다.

## 초기 확인

- 웹 검색에는 2026-10-16의 실제 관련 기사가 여러 매체에서 확인됐다.
- Mac과 OCI의 기존 Codex 로그인은 유효하다. 새 로그인/키 복사/CLI 설치는 하지 않았다.
- 최초 `gpt-5.3-codex` 점검은 이 ChatGPT 계정에서 지원하지 않는다는 오류였다.
  실제 계정의 모델 목록을 확인하고 사용할 모델을 명시적으로 정한다.

## 구현과 실제 결과

- 기본 수집 경로를 `codex_web_search`, 분류를 `codex`/`gpt-6-luna`로 전환했다.
  실제 계정 모델 목록과 정상 단건 응답을 확인했다. GDELT나 Cursor 자체의 장애를
  고쳤다는 뜻이 아니라, 해당 경로를 필수로 사용하지 않는 대안을 구현한 것이다.
- 기존 Codex 인증만 재사용한다. `--ignore-user-config`, `--ignore-rules`, `--ephemeral`,
  `--sandbox read-only`를 명시하고 shell·multi_agent·apps·plugins·remote_plugin·image_generation을
  끈다. 프로젝트 문서 자동 주입도 비활성화한다. 분류 호출에서는 웹 검색도 끈다.
- 검색은 구조화 출력으로 제목·URL·일 단위 발행일·언어만 반환한다. 원시 검색/모델 출력은
  파일로 저장하지 않는다. 후보 URL을 실제 CLI 웹 검색 이벤트의 URL과 대조하고,
  관련성·날짜·기간·중복·메타데이터를 검증한 뒤 최신 발행일순으로 선정한다.
- 웹 도구 호출은 16회·240초·출력 1 MiB로 제한한다. 예상하지 않은 도구 이벤트나 예산
  초과는 프로세스를 중단하고 실패 처리한다. 모델이 추출한 제목/날짜의 완전한 정확성을
  보증하는 것은 아니며 검색 표본임을 표시한다.
- 기본 조회 범위는 KST 발행일 14일(시작일 포함)이다. `published_at`은 YYYY-MM-DD이며
  임의의 시·분을 붙이지 않는다. GDELT의 관측 시각과 구분해 화면/필터/JSON에 반영했다.
- 새 수집은 기본 1시간 간격으로 제한한다. 표시만 다시 만들 때는 `--reuse-collection`으로
  원본 상태 검증과 분류 캐시를 재사용한다. 별도 API 키나 사용자 설정 복사는 하지 않았다.

### Mac 실데이터 end-to-end

- 자동 검색 시험에서 기사 후보 8건이 반환됐다. 이를 임의로 화면에 끼워 넣지 않고
  정식 파이프라인의 수집·선정·분류·집계·export를 다시 실행했다.
- 첫 정식 실행은 실제 기사 2건·2개 매체, 모델 호출 2회, 실패 0건으로 종료했다.
- 매체 목표를 프롬프트에 명시해 추가 검증한 실행은 실제 기사 **3건·3개 매체**, 신규
  분류 호출 2회·캐시 재사용 1건·분류 실패 0건이었다. 검색 결과는 실행에 따라 달라지며
  고정된 전체 기사 목록이라고 설명하지 않는다. 매체 5곳 목표 미달 경고도 유지했다.
- 최종 화면은 이투데이·뉴데일리·톱데일리 기사다. 발행일은 2026-10-16 두 건과
  2026-10-06 한 건이다. 2025년 기사나 주가 위젯/관련 기사 영역을 최신 뉴스로 넣지 않았다.
- 실제 제목과 발행일은 아래 원문 페이지에서도 별도로 확인했다. 앱은 전문/사진을 저장하거나
  재게시하지 않으며 분석은 제목만 근거로 한다.
- 3건은 모두 긍정으로 분류됐고 Python 집계는 긍정 3/3(100%)이다. 부정 기사를 억지로
  추가해 비율을 맞추지 않았다. 이는 선정된 작은 검색 표본이지 전체 보도/여론/객관적 평판이 아니다.
- 표시명 수정 후 재렌더링은 분류 캐시 3건을 재사용해 모델 추가 호출이 없었다.
  `ready: true`와 실제 HTTP 200, HTML 기사 요소 3개, 실명 표시 없음, 발행일 필터를 확인했다.
- 기존 미리보기 `http://127.0.0.1:51661/`에 반영했다. Safari 자동 제어는 `cgWindowNotFound`
  환경 오류로 새로고침을 검증하지 못했다. 이를 애플리케이션 오류로 숨기지 않고 HTTP/HTML로
  확인했으며 사용자가 주소에서 새로고침하도록 안내했다.

## 장애 시에도 이전 뉴스 보존

이전 구현은 `data/report.json`을 보존하면서도 화면은 빈 실패 페이지로 교체했다.
실제 뉴스가 이미 있는 경우에도 내용을 잃어 보이는 문제를 회귀 테스트로 재현해 수정했다.

- 현재 조회가 실패/0건이고 안전한 이전 정상 리포트가 있으면 화면은 `stale`로 표시한다.
- 이전 기사·분석·원래 수집 시각을 유지하고 최근 시도 상태/시각을 별도로 표시한다.
- 새 수집 성공으로 간주하지 않는다. 파이프라인의 실패/종료 코드는 유지하며 공개 전 검사는 차단한다.
- 이전 자료가 손상됐거나 표시명/모델/스키마와 호환되지 않으면 보여주지 않는다.

## 검증·실패·운영 경계

- 전체 테스트 **88개**가 Mac Python 3.14·3.12와 OCI Python 3.12에서 통과했다.
  기존 GDELT 테스트는 provider를 명시해 가상 HTTP만 사용하도록 유지했다.
- 새 테스트는 검색 이벤트/URL 증명 누락·범위 밖 날짜·위험한 URL·추가 필드·중복·발행일
  정렬/필터·예상 외 도구·호출 예산·이전 뉴스 표시를 검증한다. 가상 기사는 실제 데이터와 분리했다.
- 정상 검색 0결과를 실패로 오인하는 경우, 모든 URL이 미검증인 결과를 부분 성공으로
  남기는 경우, `회장님 회장의` 중복 표기는 먼저 실패 테스트로 재현한 뒤 수정했다.
- Ruff·JS 문법·Git diff 검사를 통과했다. 실행 데이터/분류 캐시는 Git 추적에서 제외했다.
- OCI의 기존 Codex `0.157.0`에서도 동일한 읽기 전용·도구 비활성화 옵션으로 실제 모델 단건
  JSON 응답이 성공했다. 새 설치나 인증/커널/AppArmor 변경 없이 가능함을 확인했다.
- 전체 뉴스 수집·분류는 이번에 **Mac에서 실행**했다. OCI는 임시 단위 테스트와 모델 단건
  검증뿐이며 `/srv/news-monitor` 운영 설치·서비스·타이머·Pages 배포는 아직 하지 않았다.
- 따라서 기존에 요청했던 Cursor용 AppArmor 예외는 현재 기본 경로의 필수 작업이 아니다.
  예외를 추가하지 않았다. 향후 Cursor 경로를 다시 선택하면 별도로 검토한다.

## 다음 작업

실제 샘플의 틀을 확인한 다음 수집 커버리지/반복성 보강과 OCI 운영 배포·Pages 게시를
진행한다. 의미 기반 이슈 통계는 아직 미구현이다. 새 provider는 기존 계정의 구독 쿼터를
소비하므로 호출 예산·캐시를 유지하고 수집/분류 실패를 정상 상태로 감추지 않는다.
