# 이슈·브리핑·기간별 통계 개선 계획

작성일: 2026-10-19 KST. 사용자 승인 후 구현을 시작한다.

## 목적과 순서

현재 제목 목록과 전체 비율을, 담당자가 주요 보도를 이해할 수 있는 자동 브리핑으로 개선한다.
계획 추가 → 실패 테스트 → 구현 → 실제 OCI 입력으로 검증 → Pages 배포 → wiki 기록 순서다.
기존 세 게시기·인증·타이머는 변경하지 않는다. 사람 검토를 실행 조건으로 추가하지 않는다.

1. **핵심 이슈 묶음**: 제목상 같은 사건/사업을 다루는 관련 기사를 묶고 기사 수·매체 수·
   이슈 수를 구분한다. 같은 회사/논조라는 이유만으로 별개의 사건을 합치지 않는다.
2. **핵심 브리핑**: 이슈별 한국어 한 문장과 제목 근거·원문 기사 연결을 표시한다.
   본문을 읽거나 확인하지 않은 사실을 추가하지 않는다. AI 추정·미검토임을 명시한다.
3. **기간별 통계**: 오늘·7일·30일과 매체/논조/날짜 조건에 따라 목록·요약·비율을 함께
   갱신한다. 기사 기준 통계이며 이슈별 인물 평판 점수를 만들지 않는다.
4. **주제와 수집 현황**: 경영/투자·지배구조·법원/규제·대외활동·기타 태그,
   오늘 처음 확인·이전 수집 유지·실제 조회 범위와 매체 수를 표시한다.

## 안전한 AI 처리

- 기존 Codex/gpt-6-luna 어댑터를 재사용한다. 웹·셸·파일·MCP 등 도구를 허용하지 않는다.
- 공개용으로 치환한 제목·기사 ID·발행일만 묶음 입력으로 전달한다. 전문·사진·인증은 보내지 않는다.
- 구조화 출력에서 기사 ID의 존재/중복/누락, 제목 근거, 길이·주제·날짜 간격·숫자를 검증한다.
  모델은 비율을 계산하지 않는다. 기사/매체 수와 비율은 코드가 집계한다.
- 입력 제목·모델·프롬프트가 같으면 검증한 결과를 재사용한다. 기본 최대 2회·호출당 90초·64 KiB다.
- 묶음 처리가 실패하면 기사별 제목을 쓰는 단순 표시로 내려가며, AI 이슈 분석 성공으로
  감추지 않는다. 기존 검증된 기사와 원문 링크는 유지한다.
- 구조 검증이 요약의 의미적 정확성을 보장하지는 않는다. 혐의/주장/판결을 사실로 바꾸지 않고,
  관련성 불확실·무관 기사는 핵심 이슈와 논조 분모에서 제외한다.

## 기간·추세의 의미

- 조회 기간은 새 수집부터 30일로 확대하되 선정 최대 30건·검색/분류 호출 예산은 유지한다.
- 기존 입력을 재사용한 첫 화면에는 실제로 확보한 기존 조회 범위를 그대로 표시한다.
  30일 자료가 모두 있다고 가정하지 않고, 범위 밖 날짜는 0이 아닌 '자료 범위 밖'으로 처리한다.
- 추세는 **현재 확보한 기사들의 발행일별 분포**다. 과거 각 날의 수집 결과를 보존한 일별
  스냅샷이나 전체 언론 보도량이라고 설명하지 않는다. 기간/매체 표본이 바뀌면 비교에 주의한다.
- 오늘 처음 발견한 과거 기사를 오늘 발행 기사나 오늘 발생한 이슈로 바꾸지 않는다.
- 기간/필터로 묶음 일부 기사만 남으면 전체 묶음의 AI 요약을 선택된 자료만의 결론처럼
  재사용하지 않고 선택된 제목 중심으로 표시한다.

## 구현·검증·운영

- 공개 JSON 스키마를 명시적으로 갱신하고 공개 전 검사에서 새 필드와 집계를 검증한다.
  이전 스키마의 정상 자료는 실패 시 표시용으로만 호환하며 새 배포의 준비 완료로 처리하지 않는다.
- HTML/CSS/JS/JSON 네 파일 배포를 유지한다. 사용자/모델 문자열은 HTML로 실행하지 않는다.
- Python/JavaScript에서 기간 경계(KST)·반올림·0건·보류·필터 통계를 교차 검증한다.
- 가상 테스트와 실제 뉴스는 분리한다. 실제 OCI 입력으로 기존 분류 캐시를 재사용하고
  이슈 처리만 추가 검증한 뒤 Pages의 실제 파일과 브라우저 화면을 확인한다.
- 코드·계획·결과·실패를 commit/push하고 OCI wiki의 기존 계획에 연결한다.
  운영 가이드에 새 캐시/스키마/제약을 기록한다. 승인 없는 신규 데이터 계약이나 보안 예외는 만들지 않는다.
