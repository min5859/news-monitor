# 뉴스 수집원 실측 비교

작성일: 2026-10-24 KST. 사용자 요청: Codex 웹 검색 수집이 불안정하므로 결정적 수집원 후보를
운영 상태를 바꾸지 않고 1회 실측해 비교한다.

## 배경

- 10/24 07시 정기 실행에서 검색 묶음 1의 `codex_search_budget_exhausted`가 재발했다.
  나머지 5개 묶음은 성공했지만 반환이 1건(기간 밖)·신규 0건이었다.
  `retained_articles_only`로 preflight가 게시를 막았고 서비스는 failed로 끝났다.
- 제외한 후보:
  - 네이버 검색 API: 2026-09 개정 특약이 검색 결과의 AI 입력, 복사·저장·캐싱, 가공 노출을 금지한다는 보도가 있다.
    제목 AI 분류·30일 누적·공개 게시와 충돌한다. 약관 원문은 직접 확인하지 못했다.
  - 포털 검색 페이지: search.naver.com·search.daum.net의 robots.txt가 전체 차단이다.
    언론사 사이트 검색(`/search`)도 다수 차단이라 우회 수집에 해당한다.
- 같은 날 매체 서브도메인 중복을 수정했다(`bdddc52`). 기존 14건은 다음 수집 때 13건·10개 매체로 합쳐진다.

## 방법

- 도구는 `1ac51cc`의 `news_monitor.sources`다. OCI에서 wiki-publisher로 10/24 23:44 KST에 1회 실행했다.
- 조회 기간은 KST 09/25~10/24다.
- Tavily:
  - `topic=news`, `search_depth=basic`, 검색어 3개로 3크레딧을 썼다.
  - 요약·답변·이미지·원문은 요청하지 않았다. 출력은 제목·링크·날짜뿐이다.
- 사이트맵/RSS:
  - 현재 수집 결과에 나온 매체 위주로 12개를 조회했다.
  - robots.txt가 허용하고 같은 등록 도메인인 문서만, 매체당 4개 이하로 읽었다. 기사 페이지는 열지 않았다.
  - 요청은 약 60회(robots 12, 홈 11, 문서 35)였다.
- 비교 기준은 현재 수집 14건(Codex가 원문을 열어 확인한 발행일)이다.
- 운영 data/dist/publish 파일 해시는 실행 전후 같았다. 원시 응답은 보관하지 않았다.

## 결과

  제목과 발행일이 있는 뉴스 사이트맵·RSS를 확보한 매체는 10개다.

  기준의 다른 기사 대부분은 사이트맵 보존 기간 밖이라 재현율은 오늘 측정할 수 없었다.
- 언론사가 제공하는 발행일이라 날짜 근거가 가장 정확하다.

## 결정

두 수집원은 겹침이 적고 서로 보완적이므로 둘 다 쓴다(`tavily_feeds`).
Tavily는 기간 전체와 소규모 매체를, 사이트맵/RSS는 주요 매체의 당일 기사와 언론사 제공 발행일을 맡는다.

- 수집원:
  - Tavily 검색어는 5개(하루 5크레딧)다.
  - 사이트맵·RSS는 실측에서 제목·날짜를 확인한 17개 주소를 고정 목록으로 쓴다. 문서마다 해당 호스트의 robots.txt를 확인한다.
- 날짜와 중복:
  - 같은 URL은 언론사 제공 날짜를 우선한다.
  - 공개 날짜 근거는 `reported_publication_date`이며 "일부는 갱신일일 수 있음"을 표시한다.
  - 같은 매체·같은 제목은 날짜가 달라도 한 기사로 센다.
- 제외: 회사 사이트·보도자료 배포처는 `excluded_publishers`로 뺀다.
- 이전 수집분: Codex 수집분(원문 확인 발행일)은 30일 안에서 출처와 최초 확인일을 그대로 두고 유지한다.
- 롤백: Codex 웹 검색·GDELT 경로는 설정으로 되돌릴 수 있게 남긴다.
