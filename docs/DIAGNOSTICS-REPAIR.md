# 검색·브리핑 실패 진단과 제한 복구

작성일: 2026-10-22 KST. 사용자 승인 범위: 오류 기록 보완 → 제한 재검증 → 확인된 원인 수정.

## 문제와 확인된 사실

- 10/21 검색 6개 중 2개가 일반 오류명으로 실패했고, 브리핑도 2회 실패해 fallback으로 게시됐다.
- 기존 코드는 CLI 오류/시간 제한/검증 오류를 구분하지 않거나 원래 예외를 버렸다.
  해당 시각 native Codex 진단 DB에도 관련 실행 기록이 없어 과거 직접 원인은 소급 확정하지 못했다.
- 10/22 07시 정기 실행의 검색은 6개 모두 성공했다. 기사 14건의 논조 분류는 완료됐지만
  이슈 처리는 다시 fallback이었다. 따라서 단순 대기보다 진단 가능한 상태로 보완해야 한다.

## 계획과 안전 경계

1. 실패 테스트를 먼저 추가하고 stderr/JSON 오류 이벤트를 고정된 오류 코드로 변환한다.
2. 검색은 기존 errors에 reason과 소요 시간을 남기고, 이슈는 비공개 `data/briefing_status.json`에
   단계·시도 횟수·오류 코드·소요 시간만 기록한다. 원시 응답·기사 입력·stderr·토큰은 저장하지 않는다.
3. `--briefing-only`는 최신 수집 자료와 검증된 논조 캐시만 사용한다. 검색이나 논조 AI 호출을
   금지하며 캐시가 부족하면 중단한다. 원래 수집 시각과 유효성 검사도 유지한다.
4. `--refresh-briefing --briefing-attempts 1`로 이슈 캐시를 삭제하지 않고 진단 호출을 1회로 제한한다.
   원인을 확인한 뒤 필요한 부분만 고치고, 필요한 경우 수정 후 검증 호출을 1회 추가한다.
   검색 전체 재실행·무제한 재시도·로그인 복사·모델 교체·서버 보안 변경은 하지 않는다.
5. 사용량/인증/고정 스키마 오류처럼 즉시 반복해도 해결되지 않는 오류는 추가 재시도를 중단한다.
6. 성공한 결과만 기존 공개 gate/배포 방식으로 게시한다. 검색이 부분 실패했다면 이슈 복구가
   성공해도 전체 정상이라고 설명하지 않는다. 기존 다른 세 게시기와 예약 시각은 수정하지 않는다.

## 다음 판단 기준

- 코드/검증 문제면 해당 회귀를 추가하고 수정한 뒤 게시까지 검증한다.
- 사용 한도면 자동 반복하지 않고 한도 회복 뒤의 다음 정기 실행을 관찰한다.
- 인증/설정 권한 문제면 사용자에게 필요한 최소 조치를 구체적으로 안내한다.
- 재검증이 성공해 과거 원인을 확정하지 못하면 성공한 사실과 남은 한계를 나누어 기록한다.
  이후 실패 시 오류 코드가 남으므로 같은 상태로 원인 없이 기다리지 않는다.

## 과정·결과

- 기존 실패를 가상 stderr/이벤트/검증 응답/캐시 누락으로 재현한 뒤 보완했다.
- 진단 소스 `9011aa2`를 OCI에 반영하고 서버의 Python 테스트 135개를 통과했다.
- 10/22 22:14:40–22:14:53 KST, 최신 기사 14건으로 이슈만 1회 재처리했다.
  검색/논조 호출은 0회, 논조 캐시 14건, 이슈 호출은 12.36초였다.
  응답 수신 후 validation에서 `group_evidence_not_grounded`가 발생했다.
  이 코드는 제목 인용 문구·길이·기사 ID 대응의 불일치 범주이며 원시 응답은 보존하지 않는다.
  이번 재현은 시간 초과/사용량 오류가 아니다. 10/21의 정확한 원인까지 소급 확정한 것은 아니다.
- 진단 임시 유닛 `news-monitor-diagnostic-20261022`의 exit 2는 fallback을 뜻한다.
  기존 정기 서비스 실패가 아니며 진단 결과는 공개 배포하지 않았다.
- 근거를 AI가 직접 작성하는 계약을 제거했다. AI는 이슈명·요약·주제·기사 ID만 반환하며
  코드는 연결한 실제 제목을 길이 제한 내에서 그대로 근거로 복사한다.
  기사 ID/중복/누락/날짜/숫자/한국어 및 공개 근거 검증은 유지하고 공개 스키마도 바꾸지 않았다.
- 새 계약을 재현하는 회귀 테스트가 수정 전 실패하고 수정 후 통과했다. 조작된 공개 근거가
  여전히 차단되는 테스트도 추가했다. 실제 OCI 수정 후 검증·배포 결과는 완료 후 추가한다.
