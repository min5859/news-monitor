# 뉴스 검색 호출 예산 보완

작성일: 2026-10-23 KST. 사용자 요청: 오늘 검색 호출 상한 초과가 발생한 수집기를 보완한다.

## 확인한 문제

- 10/23 07시 정기 실행의 검색 6개 중 1개가 `codex_search_budget_exhausted`였다.
  15기사·14매체·9이슈 게시와 브리핑은 성공했으나 수집은 partial이었다.
- 전체 상한 30회를 6개 묶음에 5회씩 배분한다. 검색뿐 아니라 원문 열기 등 웹 도구 호출도
  예산을 소비한다. 기존 프롬프트는 2~3개 검색어 비교와 후보별 원문 확인을 동시에 요구하고,
  처음 1~2건에서 멈추지 말라고 지시해 작은 묶음 예산과 충돌했다.

## 계획과 경계

1. 묶음별 예산·조기 종료 목표·검색/확인 호출 배분을 검증하는 회귀 테스트를 먼저 추가한다.
2. 총 상한 30회와 묶음당 5회는 늘리지 않는다. 기본 조기 종료 목표는 4회로 두고 1회를
   여유로 남긴다. 검색은 가능하면 첫 호출에 검색어를 묶고 나머지는 원문 확인에 배분한다.
3. 매체 수와 최대 기사 수는 전체 표본의 목표/상한이지 매 묶음에서 채워야 할 의무가 아니다.
   확인한 기사만 반환하고 부족하면 제외한다. URL/발행일/인물 검증을 완화하지 않는다.
4. 조기 종료 지시는 모델의 협조가 필요하다. CLI에 문서로 확인하지 못한 제어 옵션이나
   후크를 임의로 추가하지 않고 기존 이벤트 초과 차단을 유지한다. 무조건 준수한다고 보장하지 않는다.
5. 가상 이벤트/회귀와 Mac·OCI 테스트 후 기존 wiki-publisher 계정으로 ff-only 반영한다.
6. 실제 검증은 문제가 있던 첫 검색 묶음 1개·모델 1회·최대 5개 웹 이벤트로 제한한다.
   운영 collection/pipeline/게시 상태는 덮지 않고 전체 수집·재분류·재배포는 하지 않는다.
   CLI 이벤트는 이미 시작된 도구를 사후 관찰하므로 초과 이벤트 차단을 원격 호출 사전 거부로
   설명하지 않는다. 실제 준수와 다음 정기 실행 결과를 구분한다.
