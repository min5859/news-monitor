# 3단계 — AI 분류·집계·정적 화면

작업일: 2026-10-18 KST.

## 계획과 성공 조건

1. 기존 호출 대기를 지키며 수집 상태를 확인한다. 실패를 정상 0건으로 바꾸지 않는다.
2. 제목만 제공하는 Cursor 분류기를 구현한다. 관련성·논조·근거를 검증하고 실패는 보류한다.
3. Python에서 관련·분류 완료 기사만 분모로 집계하고 0건은 비율 산출 불가로 표시한다.
4. 공개 허용 필드만 정적 HTML/CSS/JS로 내보낸다. 실패·0건·자료 시각·미검토 상태를 표시한다.
5. 가상 테스트와 실제 수집 검증을 분리하고 Mac·OCI 임시 경로에서 검증한다.
6. 구현·검증·실패·잔여 작업을 이 문서와 OCI wiki에 기록한다.

이번 단계는 로컬 구현과 격리 검증이다. GitHub Pages 활성화·OCI 운영 설치·정기 타이머는
다음 배포 단계에서 다룬다. 기존 세 게시 프로젝트의 설정·인증·스케줄은 수정하지 않는다.

## 현재 확인한 제약

- 12:16 KST 실제 GDELT 재확인도 HTTP 429였다. 다음 요청 가능 시각은 12:31:36 KST 이후다.
  새 실기사 데이터는 아직 확보하지 못했고 다른 IP로 우회하지 않는다.
- Mac Cursor CLI는 설치되어 있지만 현재 인증이 없다. 인증 정보를 프로젝트로 복사하지 않는다.
- 가상 기사는 자동 테스트에만 사용한다. 공개 뉴스 목록이나 실제 통계에 섞지 않는다.

## 구현 결과

- `analysis.py`: Cursor ask 모드·임시 workspace·도구 권한 거부·강제 샌드박스 실행.
  외부 제목은 명령이 아닌 JSON 입력으로 전달하며 원문 URL·본문·인증 정보를 넣지 않는다.
  프롬프트는 stdin으로 전달한다. 기존 사용자 설정이나 인증 파일을 수정·복사하지 않는다.
- 관련성 3종과 논조 5종, 정확한 키 집합, 중복 JSON 키 거부, 한국어 이유 길이,
  실제 제목에 있는 근거를 검증한다. 불확실·관련 없음은 반드시 판단 보류다.
- 기본 호출당 90초·전체 30회(재시도 포함)·stdout/stderr 합계 64 KiB를 제한한다.
  시간/크기 초과 시 별도 프로세스 그룹을 종료한다. 원시 출력과 stderr는 앱 산출물에 저장하지 않는다.
- 제목·대상·모델·프롬프트 SHA-256 기준으로 검증한 응답만 캐시한다. 실패는 캐시하지 않는다.
  프롬프트 변경은 버전 해시를 바꿔 이전 분류를 재사용하지 않도록 한다.
- `report.py`: 최신 상태와 기사 파일의 일치·24시간 이내 유효성·관측 기간·안전한 URL·
  도메인·기사 ID·중복·대상 조건을 다시 확인한다. 임의 추가 필드는 공개 export에 포함하지 않는다.
- 집계는 Python이 계산한다. 관련·분류 완료 기사만 분모이며 판단 보류·관련 없음은 제외한다.
  0.1% 단위 최대 나머지 방식으로 합계를 100%로 맞추고, 분모 0은 `null`/산출 불가다.
  긍정 대 부정만의 보조 지표는 별도 분모와 제외 항목을 표시한다.
- `run.py`: 수집→검증→분류/보류→집계→로컬 화면 생성. 같은 data-dir의 잠금을 전체 흐름에
  적용한다. 실패·0건 시 기존 `data/report.json`을 보존하고 최근 파이프라인 상태를 기록한다.
- `site.py`와 `web/`: 정적 HTML/CSS/JS, 현황·논조 분포·매체별 건수·기사 목록·필터.
  KST 관측일과 발행일을 구분하고 AI 미검토·범위·모델/프롬프트·출처를 표시한다.
  모델 장애와 정상 판단 보류를 구분한다. 의미 기반 이슈 묶음/이슈 통계는 아직 미구현이다.
- 출력은 `index.html`, `styles.css`, `app.js`, `report.json` 네 파일뿐이다. 다른 파일이 있는
  출력 폴더는 거부한다. 기사 문자열 HTML 이스케이프·외부 링크 보호·제한적 CSP를 적용하고
  JS는 `innerHTML`로 기사 내용을 주입하지 않는다. 폴더 전체를 복사해 배포하지 않는다.
- `dist/`는 Git 추적 제외다. `dist/report.json`은 이번 화면 데이터이며 실패는 수치가 `null`이다.
  마지막 비어 있지 않은 `data/report.json`과 혼동하지 않는다. 실패 화면의 생성이 수집 성공은 아니다.

## 검증과 실패 기록

- Mac Python 3.14·3.12와 OCI Ubuntu Python 3.12에서 전체 테스트 62개 통과.
  가상 입력의 전체 연결·캐시·잘못된 스키마·허위 근거·실패/0건·분모·반올림·위험한 URL·
  공개 필드·XSS 이스케이프·프로세스 시간/출력 제한을 검증했다.
- 검증 중 발견한 누락 기사 파일과 출력 오류 시 예전 성공 상태가 남는 경우를
  실패 테스트로 재현해 수정했다. 잘못된 설정도 최근 파이프라인 실패로 기록한다.
- 입력을 읽지 않는 자식 프로세스에서는 stdin 쓰기가 시간 제한 밖에서 대기할 수 있음을
  추가 실패 테스트로 재현했다. 비차단 stdin 전송으로 바꿔 입력 전송부터 종료까지 제한한다.
- Ruff·JavaScript 문법·Git diff 검사 통과. 첫 정적 검사에서 발견한 import/type 오류는 수정했다.
- Safari에서 실제 실패 화면을 확인했다. 수치 확인 불가·분석 범위·수집 시각을 표시한다.
  별도 `/tmp`의 가상 데이터 5건에는 실제 뉴스가 아니라는 표시를 넣고, 분류 완료 4건·보류 1건·
  각 논조 25%·긍정 대 부정 보조 비율 50/50을 확인했다. 이는 실제 뉴스 결과가 아니다.
- 브라우저에서 긍정 필터는 1/5건, 모순되는 매체 필터 조합은 0/5건과 빈 결과 안내를
  표시했다. 상단 집계는 그대로 유지됐다. 모바일 반응형 CSS는 구현했으나 실기기 검증은 미수행이다.
- 기본 Python 3.14 미리보기 서버가 즉시 준비되지 않아 해당 테스트 서버만 종료했다.
  호스트명 역조회에 의존하지 않는 임시 Python 3.12 서버로 HTTP 200·브라우저 QA를 수행했다.
  다른 로컬 서버는 종료하거나 변경하지 않았다.
- 검증 후 전용 임시 코드·가상 데이터·미리보기 서버를 정리했다. OCI 임시 검사에서
  다른 계정의 시작 디렉터리 권한 경고가 있었으나 `/tmp`를 작업 디렉터리로 지정해
  정리 완료를 확인했다. 기존 계정의 홈 권한은 바꾸지 않았다.
- 로컬 임시 폴더의 재귀 강제 삭제는 도구가 거부했다. 파일 목록을 확인한 뒤
  정확한 테스트 파일만 개별 삭제하고 빈 디렉터리를 제거하는 방식으로 정리했다.
- 대기 만료 후 **12:32 KST**에 기본 파이프라인을 한 차례 더 실행했으나 다시 HTTP 429였다.
  exit 1·모델 호출 0회·수치 `null`인 실패 화면을 확인했다. 다음 요청 가능 시각은
  **12:47:31 KST 이후**로 보존했으며 추가 재시도나 자동 예약은 하지 않았다.

### 실제 모델 호출 — 미통과

- Mac `agent --list-models`는 인증 필요 오류였다. 신규 로그인·API 키 발급은 수행하지 않았다.
- OCI `wiki-publisher`의 기존 CLI는 `2026.10.16-e3cb207`이며 모델 목록에
  `claude-sonnet-5-5-medium`이 있는 것을 확인했다. CLI 재설치는 하지 않았다.
- 임시 경로의 가상 제목 한 건으로 호출했으나 강제 샌드박스 초기화에서 종료됐다.
  모델 분류 결과는 확보하지 못했으며 앱이 이를 판단 보류/실패로 처리함을 확인했다.
- 최초 비로그인 셸 호출은 CLI PATH가 맞지 않아 실패했다. 기존 로그인 셸 PATH로
  다시 확인해 위 샌드박스 오류를 분리했다. 인증 파일을 복사해서 해결하지 않았다.
- CLI는 `Sandbox mode is enabled but not available`을 보고했고 AppArmor 가능성을 안내했다.
  `bwrap` 명령은 발견되지 않았지만 정확한 원인을 이것만으로 확정하지 않는다.
- **강제 샌드박스는 이 신규 분류기에 추가한 보호 조건**이다. 기존 게시기 장애로 해석하지 않는다.
  우회 실행·전역 `agent sandbox disable`·AppArmor/커널 설정 완화·추가 패키지 설치는 하지 않았다.
- 실제 Cursor의 허용된 환경에서 응답 형식·한국어 근거·캐시까지 연결하는 검증은 아직 남아 있다.
  프롬프트/스키마 단위 테스트 통과가 실제 모델 분류 품질을 보증하지 않는다.

## 실행과 다음 단계

```bash
# 기본 흐름: API 호출 대기와 수집 상태 검사를 지킨다.
python3 -B -m news_monitor.run

# API 재호출 없이 최근 파일로 로컬 화면만 확인한다. 오래되거나 불일치한 자료는 거부한다.
python3 -B -m news_monitor.run --reuse-collection
```

`ok`는 exit 0, 실패는 1, 부분 성공·정상 0건은 2다. 실패를 무시하고 후속 배포를 실행하면 안 된다.
이번 작업의 `dist/`는 수집 실패 안내 화면이며 실제 뉴스 비율을 담은 공개 샘플이 아니다.

남은 순서는 실제 수집 경로 정상화 → 안전한 Cursor 실행 환경 검증 → 실뉴스 end-to-end 확인 →
공개 필드/산출물 점검 → 별도 OCI 운영 경로·Pages 배포 검증이다. 사람의 기사 선정이나 검토를
필수 단계로 새로 넣지 않았다. 기존 OCI 서비스·인증·타이머·계정과 서버 보안 설정은 변경하지 않았다.
OCI 작업은 ubuntu의 임시 단위 테스트와 wiki-publisher의 임시 가상 호출 검사뿐이다.
