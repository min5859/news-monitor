# 2단계 — 자동 수집 안정화

확인일: 2026-10-18 KST.

## 범위와 결과

독립 프로젝트 `news-monitor`의 수집기만 보강했다. 기사 수동 입력이나 사람 검토를
추가하지 않았다. 코드 안정화와 실제 다매체 기사 확보는 별개의 완료 조건이다.
**안정화 코드·격리 검증은 완료했지만 실제 수집 검증은 여전히 미완료**다.

## 변경 내용

- 조회 기간을 7일에서 14일로 확대하고 회사명·영문 인명 별칭을 단일 OR 검색으로 묶었다.
  검색당 최대 30건과 제목 내 인물·회사 동시 확인 조건은 유지했다.
- HTTP 429는 재시도·후속 쿼리를 즉시 중단한다. 기본 900초와 Retry-After 중 긴 시간을
  요청 완료 시점부터 적용하고 `request_state.json`에 기록한다.
- 재시도 가능한 503 등의 긴 Retry-After도 호출 대기로 보존한다. 짧은 장애만 제한 재시도한다.
- 정상 실행 후에도 기본 60초 간격을 두고, 재실행 시 대기 중이면 요청 없이 실패 종료한다.
- 동일 data-dir의 OS 파일 잠금으로 동시 실행과 결과 파일 충돌을 막는다. 프로세스가
  종료되면 잠금은 OS가 해제한다. 잠금 파일의 존재나 오래된 수정 시각만 보고 삭제하지 않는다.
- 설정 파싱 오류가 발생했는데 이전 `ok` 상태가 남던 문제를 재현하고 수정했다.
  손상된 요청 상태는 실패로 처리하며 초기화 후 자동 재요청하지 않는다.
- 회사만/인물만/둘 다 없는 제목의 제외 건수, 계획·시도·성공한 검색 수, 매체 수와
  목표 달성 여부를 기록한다. 매체 5곳 목표 미달은 경고이지 임의 기사 추가 조건이 아니다.
- 기존 정상 기사 파일은 실패·0건·대기 중에도 보존한다. 후속 단계는 반드시 최근 상태와
  기사 데이터의 시각을 함께 확인해야 하며 오래된 기사로 새 성공 결과를 만들어서는 안 된다.

재실행 간 제한은 같은 data-dir을 이용하는 수집기에 적용된다. 다른 수집 프로그램이나
기기까지 통제하지 않는다. 별도 경로를 지정해 대기 상태를 회피하면 안 된다.

## 테스트와 실환경 검증

- 먼저 기존 코드에서 새 회귀 테스트 9개의 실패/오류를 확인한 뒤 구현했다.
- 총 35개 가상 메타데이터 테스트가 Mac Python 3.14·3.12와 OCI Ubuntu Python 3.12에서 통과했다.
- 429 즉시 중단·기본 대기·긴 Retry-After·부분 성공 보존·재실행 대기·만료 후 재개·
  동시 실행 차단·손상 상태·설정 오류·제외 통계·매체 목표 미달을 검증했다.
- Ruff와 Git diff 검사를 통과했다. 테스트 자료는 실제 기사·공개 통계로 사용하지 않았다.
- OCI 검증은 ubuntu의 임시 `/tmp` 작업 경로에서 단위 테스트만 실행했다. 기존 서비스와
  인증 정보를 수정하지 않았으며 검증 후 임시 복사본을 제거했다.
- 최초 Mac tar 전송에서 확장 속성 경고와 `._` 보조 파일이 생겨 빈 디렉터리 삭제가
  한 번 실패했다. 보조 파일까지 지정해 제거했으며, 후속 전송은 확장 속성을 제외했다.

## 실제 API 시도와 실패 기록

- 기존 단일 회사 검색은 Python 3.14와 3.12 모두 HTTP 429였다. 같은 조건에서 버전을
  바꿔도 재현되어 Python 버전 차이를 원인이나 해결책으로 판단하지 않았다.
- 개선한 수집기의 14일 OR 검색도 HTTP 429를 반환했다. 응답 기사 확보 전 실패했으므로
  이 시도의 '선정 0건'을 해당 기간에 관련 뉴스가 없다는 의미로 해석하지 않는다.
- 재시도 가능 시각은 이 시도에서 **2026-10-18 10:06:45 KST 이후**로 기록됐다.
  자동 예약·백그라운드 재실행을 설치했다는 뜻이 아니다.
- 그 전에 CLI를 재실행했을 때 즉시 `request_cooldown`으로 종료되는 것을 확인했다.
  원격 호출을 반복하거나 OCI IP·프록시·브라우저 위장으로 차단을 회피하지 않았다.
- 현재 시도에서 실제 대상 기사 데이터는 새로 확보하지 못했다. 지난 단건 진단의
  5건·5매체 응답을 이번 실행의 성공 결과로 재사용하지 않았다.
- 서버 측 제한의 정확한 적용 범위·원인은 이 응답만으로 확정할 수 없다. 대기 로직은
  우리 수집기의 반복 호출을 줄이는 조치이며 외부 API 가용성 해결을 보장하지 않는다.

## 대체 경로 검토

네이버 뉴스 검색 API는 공식 검색 경로이나 개발자 FAQ에 단순 캐시 외의 별도
저장·재가공 제한이 명시되어 있다. 키 발급만으로 저장·AI 분석·공개가 허용된다고
가정하지 않고 이번 단계에는 연동하지 않았다. Google News RSS 제외도 유지한다.

사용자에게 기사 선정을 요청하지 않는다. 다음 수집 검증은 기록된 대기 이후에 수행하며,
429가 지속되면 이용 조건이 맞는 다른 자동 공급 경로 검토 또는 공급자 문의가 필요하다.
유료 계약·외부 문의·추가 계정 발급은 이번 작업에서 진행하지 않았다.

## 아직 하지 않은 작업

AI 호출·논조 분류·통계·화면·GitHub Pages·OCI `/srv/news-monitor` 설치·서비스/타이머 등록은
아직 하지 않았다. 기존 Dev Blog·Research Wiki·OSS Radar 운영본도 변경하지 않았다.
다매체 실수집이 검증되지 않은 상태를 샘플 완성이나 정기 운영 가능 상태로 표시하지 않는다.
