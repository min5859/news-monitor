작업일: 2026-10-19 KST. OCI 설치·첫 공개 배포·예약 활성화 완료. 첫 정기 실행 검증 전이다.

## 계획

상세 설계는 [일일 배포 계획](DAILY-PUBLISHING.md)을 따른다. 수집 개선 → 실제 OCI 실행 → 공개 전 검사 →
Pages 첫 배포 → 매일 07:00 KST 타이머 활성화 순서로 진행한다.
기존 Dev Blog·Research Wiki·OSS Radar 서비스와 인증은 변경하지 않는다.

## 수집 개선

- 한글 인물/회사·직함·영문명 검색어를 3개 묶음으로 분리해 코드에서 각각 실행한다.
  전체 웹 호출 한도 24회와 시간 600초를 묶음에 배분한다. 실패한 묶음의 미확인 소비량도
  예약 예산으로 계산해 재할당하지 않는다. 묶음 일부 실패는 부분 성공으로 기록한다.
- 제목에 대상 인물명은 유지하되 회사명 생략 후보도 분류기에 전달한다.
  동명이인/회사 일반 뉴스는 관련으로 확정하지 않으며 보류·무관은 논조 분모에서 제외한다.
- 실제 검색 이벤트의 URL·발행일·기간·공개 URL 검증을 유지한다.
- 이전 수집 파일을 원래 확인 시각에서 검증한 뒤, 현재 발행일 범위의 기사만 새 결과와
  URL 기준으로 누적한다. 실패한 새 검색에 이전 자료를 합쳐 성공으로 만들지 않는다.
- 최초 확인일과 최근 확인일을 보존하고 재사용 기사는 화면에서 표시한다.
  새로 확인한 기사가 0건이면 `retained_articles_only` 경고로 공개 전 검사를 차단한다.
- 당일 발행 기사 수·논조 비율을 전체 14일 분포와 분리한다. 분모 0은 산출 불가다.

## 검증과 실패 기록

- 먼저 검색 묶음·부분 실패·누적·재확인·기한 만료·인물명만 있는 제목의 실패 테스트를
  추가해 기존 구현의 8건 실패를 확인한 뒤 수정했다.
- Mac Python 3.14와 3.12에서 기존 포함 99개 테스트, Ruff·JS 문법·diff 검사가 통과했다.
- 정적 검사에서 import 정렬 2곳이 지적되어 정렬했다. 테스트용 데이터는 실제 수집과 분리한다.
- 첫 소스 commit은 75자 줄 제한 사전 검증에 차단되어 실행하지 않았다. 메시지를 줄여
  검증한 뒤 commit/push했다. 이 실패로 소스나 원격 이력을 되돌리지는 않았다.
- OCI의 `wiki-publisher`에는 GitHub CLI 인증이 없었다. 다른 프로젝트 토큰은 읽거나
  복사하지 않았다. 뉴스 저장소 전용 배포 키를 사용하고 서버의 기존 Codex 로그인은 유지한다.
- 운영 설치·실제 수집·배포 결과는 각각 완료 후 이 문서에 추가한다.

## OCI 첫 실제 실행과 추가 개선

- 소스 `290aa28`을 `/srv/news-monitor/app`에 root 소유로 설치했다. 데이터·산출물·배포
  작업 디렉터리는 `wiki-publisher` 소유 0700이다. 새 사용자/CLI/로그인은 만들지 않았다.
- 동일한 99개 테스트가 OCI Python 3.12에서도 통과했다.
- 2026-10-19 09:20~09:21 KST 임시 oneshot 유닛으로 실제 수집·분류를 수행했다.
  검색 묶음 3개 모두 성공, 웹 도구 12회, 기사 3건·매체 3곳, 분류 호출 3회·실패 0건이다.
  데일리e뉴스(10/16)·톱데일리(10/06)·Korea Times(10/06)이며 원문 제목·발행일도 확인했다.
  당일 발행 기사를 확보한 것은 아니며 매체 5곳 목표 경고를 유지했다.
- 3건 확보에 그쳐 언론사 도메인 중립 검색을 추가했다. 최종 설정은 통신사·경제지·
  일반/영문 보도 **6개 묶음, 전체 30회·600초**다. 이는 검색 범위를 늘린 것이며
  6곳의 직접 API/RSS를 새로 연동했다는 뜻은 아니다. 이 최종 묶음의 실수집 검증은 별도다.
- URL뿐 아니라 같은 매체·정규화 제목·발행일이 같은 기사도 중복 제거한다.
  같은 URL의 제목 수정은 새 버전을 쓰되 최초 확인일을 유지한다.
- Mac에서 이미 자동 검증한 메타데이터를 OCI로 이관해 누적할 예정이다.
  인증/원시 모델 응답은 옮기지 않고 이전 기사의 확인 시각을 새 시각으로 바꾸지 않는다.

## 배포 구현과 검증

- `news_monitor.publish`는 공개 전 검사를 통과한 4개 파일만 별도 Git 작업 디렉터리에서
  `pages-data`에 push한다. 기존 수동 변경·추가 파일·심볼릭 링크·브랜치 분기는 중단하며
  force push/reset을 사용하지 않는다. Git hook과 다른 Git 자격 증명 설정은 로드하지 않는다.
- push 성공은 `pushed`, 공개 URL의 네 파일이 실제 push한 바이트와 같으면 `published`로
  구분한다. 이전 JSON을 반환하는 HTTP 200은 성공으로 간주하지 않고 180초 한도로 확인한다.
- 분류 호출 실패가 있는 결과나 이전 기사만 재사용한 결과는 새 배포를 차단한다.
- 서버에서 뉴스 저장소 전용 ed25519 키를 생성했다. 개인키는 서버에만 있고 GitHub에는
  공개키만 등록했다(키 ID `166885129`). 저장소 전체 쓰기 키이며 브랜치 제한 키는 아니다.
  다른 프로젝트 접근 권한은 없지만 만료가 없으므로 필요 시 키를 철회/교체한다.
- SSH 호스트 키는 GitHub 공식 `/meta` API에서 가져와 전용 known_hosts로 고정했다.
  호스트 검증을 끄거나 무검증 keyscan 결과를 신뢰하지 않았다.
- 임시 로컬 Git 원격을 이용한 push·변경 없음 재실행·실패 gate·수동 파일 보호·실제 공개
  파일 검증 테스트를 추가했다. 전체 108개 테스트와 Ruff·JS/Bash 문법·diff 검사 통과.
- systemd service/timer와 실행 래퍼를 소스에 추가했다. 실제 유닛 설치/활성화와 Pages 결과는
  해당 작업이 끝난 뒤 아래에 기록한다.

## 이관·최초 공개·예약 활성화 결과

- Mac의 기존 자동 수집 메타데이터를 정식 검증/누적 함수로 OCI 자료와 합쳤다.
  OCI 확인 3건 중 1건은 이전 기사 재확인이었고, 이전 기사 2건을 추가 유지해
  최종 **5건·5개 매체**다. 5건을 오늘 모두 새로 수집했다고 설명하지 않는다.
- 추가 2건의 분류 호출이 성공했고 기존 OCI 캐시 3건을 재사용했다. 분류 실패 0건,
  긍정 5/5(100%)·부정/중립/혼합 0이다. 작은 검색 표본이며 전체 여론이 아니다.
- 공개 전 검사 10항목을 통과했다. 당일인 10/19 발행 기사는 0건으로 분리 표시하며
  이는 당일 전체 언론 보도 0건을 의미하지 않는다.
- `pages-data` commit `9f2dee043538ceb7c5c647366d80235290a4b58b`에는 네 정적 파일만 있다.
  Pages의 게시 소스를 해당 브랜치 루트로 설정했다. 자체 워크플로는 추가하지 않았다.
- GitHub Actions 실행 `39180860281`의 build/deploy가 성공했다. 09:28:15 KST에 OCI에서
  공개 URL의 네 파일이 push한 바이트와 일치함을 확인했고 `published`로 기록했다.
- 공개 주소: <https://min5859.github.io/news-monitor/>. Safari에서도 5건·5매체·당일 0건·
  발행일 범위·이전 기사 표시·`회장님` 표기와 실제 화면 레이아웃을 확인했다.
  모바일 폭/필터 상호작용을 이번에 추가로 조작 검증하지는 않았다.
- `news-monitor.timer`를 enable/start했다. 다음 예약은 UTC 2026-10-19 22:00:22,
  즉 **2026-10-20 07:00:22 KST**다. 정식 service는 아직 예약 실행 전이고,
  오늘은 임시 수집 유닛과 첫 배포 명령을 단계별로 실행했다.
- 기존 세 타이머의 예약은 그대로 유지됐다. 소스 root 소유/읽기 전용, 운영 폴더 0700,
  개인키 0600과 service/timer 구문 검사를 확인했다.
- 유닛 검증 중 기존 Oracle unified-monitoring-agent 유닛의 실행 권한 경고가 나왔다.
  뉴스 유닛 오류가 아니며 범위 밖이므로 해당 파일을 바꾸지 않았다.
- 최종 검토에서 응답/누적 건수 상한에 도달한 상태를 정상 전체 성공으로 남기는 경계를
  실패 테스트 2개로 재현해 부분 성공·제외 건수로 수정했다.
- 최종 전체 테스트 110개가 Mac Python 3.14·3.12에서 통과했고 Ruff·JS/Bash·diff도 통과했다.
  최종 코드 `2eabf73`을 OCI에 설치한 뒤 Python 3.12의 110개 테스트와 공개 전 검사 10개도
  다시 통과했다. OCI 소스 작업 트리의 수동 변경은 없고 타이머 active/다음 예약을 재확인했다.
- 소스 코드와 실행 설정은 `290aa28`, `561fbb9`에 commit/push했다. 최종 검토 수정·운영
  기록은 후속 commit에 포함한다. 실행 데이터·개인키·원시 출력은 소스 Git에 넣지 않았다.
- 운영 경로·Health Check·재시도·중단·자격 증명/용량 점검은 [운영 가이드](OCI-OPERATIONS.md)에 정리했다.
  OCI wiki의 기존 계획서도 현재 상태로 갱신한다. 임시 이관 JSON은 검증 뒤 삭제했다.
- 공개 사이트를 기존 미리보기 탭에 열고, 사용하지 않는 Mac 임시 서버(PID 32339,
  127.0.0.1:51661)는 명령/작업 경로를 확인한 뒤 종료했다. 로컬 소스·데이터는 삭제하지 않았다.
