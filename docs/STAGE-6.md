## 수집 개선

- 한글 인물/회사·직함·영문명 검색어를 3개 묶음으로 분리해 코드에서 각각 실행한다.
  전체 웹 호출 한도 24회와 시간 600초를 묶음에 배분한다. 실패한 묶음의 미확인 소비량도
  예약 예산으로 계산해 재할당하지 않는다. 묶음 일부 실패는 부분 성공으로 기록한다.
- 제목에 대상 인물명은 유지하되 회사명 생략 후보도 분류기에 전달한다.
  동명이인/회사 일반 뉴스는 관련으로 확정하지 않으며 보류·무관은 논조 분모에서 제외한다.
- 실제 검색 이벤트의 URL·발행일·기간·공개 URL 검증을 유지한다.
- 이전 수집 파일을 원래 확인 시각에서 검증한 뒤, 현재 발행일 범위의 기사만 새 결과와
  URL 기준으로 누적한다. 실패한 새 검색에 이전 자료를 합쳐 성공으로 만들지 않는다.
- 최초 확인일과 최근 확인일을 보존하고 재사용 기사는 화면에서 표시한다.
  새로 확인한 기사가 0건이면 `retained_articles_only` 경고로 공개 전 검사를 차단한다.
- 당일 발행 기사 수·논조 비율을 전체 14일 분포와 분리한다. 분모 0은 산출 불가다.

## 검증과 실패 기록

- 먼저 검색 묶음·부분 실패·누적·재확인·기한 만료·인물명만 있는 제목의 실패 테스트를
  추가해 기존 구현의 8건 실패를 확인한 뒤 수정했다.
- Mac Python 3.14와 3.12에서 기존 포함 99개 테스트, Ruff·JS 문법·diff 검사가 통과했다.
- 정적 검사에서 import 정렬 2곳이 지적되어 정렬했다. 테스트용 데이터는 실제 수집과 분리한다.
- OCI의 `wiki-publisher`에는 GitHub CLI 인증이 없었다. 다른 프로젝트 토큰은 읽거나
  복사하지 않았다. 뉴스 저장소 전용 배포 키를 사용하고 서버의 기존 Codex 로그인은 유지한다.
- 운영 설치·실제 수집·배포 결과는 각각 완료 후 이 문서에 추가한다.
