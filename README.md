# News Monitor — 효성 조현준 회장 뉴스 샘플

저장소: [min5859/news-monitor](https://github.com/min5859/news-monitor) (public).
2026-10-18 코드 원격 보관을 완료했다. GitHub Pages와 OCI 운영 배포는 아직 활성화하지 않았다.

현재는 **1단계 자동 수집기 구현 및 수집 경로 검증**이다.
AI 논조 분류·통계·웹 화면·GitHub Pages 게시·정기 운영은 아직 구현하지 않았다.
기사 목록의 수동 준비나 사람 검토를 선행 조건으로 두지 않는다.

## 실행

Python 3.11 이상, 추가 Python 패키지 없이 실행한다.

```bash
python3 -B -m news_monitor.collect
python3 -B -m unittest discover -s tests -v
```

대상 별칭·조회 기간·건수·API 설정과 호출 제한은 `config.json`에 있다.
기본값은 GDELT DOC API, 최근 관측 7일, API 결과 최대 30건이다.
요청마다 별도의 전체 기사 사이트 크롤링이나 이미지 다운로드를 하지 않는다.

## 산출물과 상태

- `data/articles.json`: 수집 성공/부분 성공 시 자동 선정된 메타데이터. Git 추적 제외.
- `data/collection_status.json`: 최근 시도 상태·수집 범위·제외 건수·출처·오류.
- `ok`/exit 0: 요청·메타데이터 처리 정상, 관련 기사 존재. 전수 수집 보장은 아니다.
- `empty`/exit 2: 요청 정상이나 조건에 맞는 기사 없음. 잘못된 응답과 구분한다.
- `partial`/exit 2: 일부 요청·메타데이터 실패 또는 API 결과 상한에 도달.
- `failed`/exit 1: 요청 전부 실패하거나 응답 데이터가 잘못됨.

실패·0건 시 이전 `articles.json`을 지우거나 빈 목록으로 덮어쓰지 않는다.
후속 단계는 반드시 `collection_status.json`도 확인해야 한다. 이전에 저장된 파일을
이번 실행의 새 기사로 오인하면 안 된다. 부분 성공은 경고를 유지한다.

## 선정과 한계

- 제목에 대상 인물 별칭과 효성 별칭이 함께 확인되는 경우만 보수적으로 선정한다.
  이름이 본문에만 등장하는 기사는 놓칠 수 있다. 본문을 읽었다고 주장하지 않는다.
- GDELT `seendate`는 관측 시각이다. 발행 시각으로 바꾸지 않고 `published_at`은 null로 둔다.
- UTC 관측 기간 필터·URL 정규화·추적 파라미터 제거·최신 관측순 선정을 적용한다.
- 다른 매체의 같은 제목을 모두 삭제하지 않는다. 같은 이슈 묶기는 후속 단계다.
- API의 `domain`과 기사 URL 호스트를 대조하고, 위험한 URL·잘못된 날짜·HTML 응답을 거부한다.
- 저장하는 것은 제목·원문 링크·매체 도메인·언어·시각 등 명시한 필드뿐이다.
  기사 전문·사진·원시 API 응답은 저장하지 않는다.
- source attribution을 후속 공개 산출물에서도 유지해야 한다.

## 진행 단계

1. 저장소 생성·코드 push: 완료. 코드·문서만 보관하며 실행 데이터는 제외한다.
2. 자동 수집 안정화: 수집기 구현·테스트 완료, 실제 가용성·다매체 대상 기사 확보는 검증 중.
3. AI 분류·통계·정적 화면: 미구현. 자료 부족은 판단 보류, 실패·0건은 구분한다.
4. OCI 배포·공개 샘플 게시: 미수행. 비밀값·원문 제외 후 GitHub Pages를 검증한다.

현재 기존 OCI 세 게시 서비스, 타이머, 인증 파일은 변경하지 않았다.
상세 근거와 실패 기록은 [1단계 검증 기록](docs/STAGE-1.md)에 남긴다.
