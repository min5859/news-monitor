# Lessons

## 2026-10-24: 기술 판단을 사용자에게 떠넘기지 않는다

- 상황: 수집원 실측을 직접 설계·실행하고 근거까지 정리한 뒤 "A/B/A+B 중 무엇으로 할까요?"라고 물었다.
- 사용자 피드백: "그건 나한테 물어보면 안 되지. 네가 제안해서 진행한건데."
- 규칙: 실측·근거가 있는 기술 선택(수집원, 구조, 표시 방식)은 직접 결정하고 근거와 함께 진행한다.
  사용자에게는 권한·비용·계정·약관·외부 공개처럼 사용자만 결정할 수 있는 것만 묻는다.

- 모델이 지켜야 하는 수치 규칙(날짜 간격 등)은 프롬프트로 강제되지 않는다. 운영 입력으로 재현해 확인한 뒤, 검증 게이트는 그대로 두고 코드에서 결정적으로 맞춘다.

- (사용자 정정 10/25) 보고는 사용자가 판단할 수 있게 쓴다. 문제마다 ①무엇이 문제인지(쉬운 말) ②영향(지금·방치 시, 숫자) ③제안(추천안·이유·사용자가 할 일)을 붙인다. 코드명·용어만 나열하거나 "판단 필요"로 넘기지 않는다. 기술 판단은 내가 하고, 승인이 필요한 것만 근거와 함께 묻는다.
